Privacy at fold.pdf

The privacy path depends on how you add a file. This page separates local device processing from optional remote imports so you can choose appropriately.

Files selected from your device

When you choose PDFs or supported images from your device, fold.pdf processes those files in your browser. The application does not intentionally upload those local file bytes to a fold.pdf document-processing server. Merging, splitting, page organization, and visual-signature placement are performed with browser-side PDF libraries.

URL and Google Drive imports

If you use Import from URL or Google Drive, the link is sent to a fold.pdf serverless proxy. The proxy retrieves the remote document and returns it to your browser. The document therefore transits the hosting provider, and the URL—including a Drive ID or signed-link token—may be visible in ordinary hosting or request logs. The proxy sends no-store cache headers, but this repository does not define the hosting provider’s log retention.

Most private workflow: download the remote document yourself, then select that local file in fold.pdf.

Remote-import safeguards

The proxy accepts HTTPS PDF, JPG, PNG, and WebP responses, limits redirects, blocks resolved private and local network addresses, applies a timeout and size cap, validates response types, and does not expose wildcard cross-origin access. These controls reduce abuse; they are not malware scanning and cannot guarantee that every remote file is safe.

Visual signatures

Sign mode creates a reusable image of what you draw or type and embeds that image into the exported PDF. It does not verify identity, create a certificate-based signature, provide tamper evidence, or encrypt the file. Exporting a modified PDF can invalidate an existing cryptographic signature.

Third-party browser resources

The public pages may request fonts from Google Fonts. The workspace loads pinned PDF libraries and a PDF worker from cdnjs. Those providers receive ordinary web-request information such as an IP address and browser headers; they do not intentionally receive your locally selected document from the application.

Clearing the workspace

Clear all removes files, page state, placed signatures, and the current signature from the interface and releases browser object URLs and PDF.js document resources. Browser JavaScript cannot promise forensic or secure memory erasure; closing the tab is the strongest practical end to the session.
